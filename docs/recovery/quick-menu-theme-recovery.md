# Quick Menu theme material follow-up

Static read-only evidence from app.exe (cached 6.00), PUI.dll and already recovered work/footer-firmware/Theme.dll. The earlier materials-audio.md identifies this Theme/PUI cache as recovered 6.00 firmware. No production file changed and no runtime was launched.

The constructor's rgba(21,21,44,.94) is only the initial background. It is replaced by the theme skin when applied. For the recovered blue theme the resulting material is **rgba(3,29,97,250/255)**, CSS #031d61 with alpha .9803921569. This is a conditional blue-theme value, not a universal fixed color.

Exact chain:

- app MenuPanel ctor 06008AF2 IL006D–0086 sets initial RGBA; IL0097–0099 sets SkinApplyWidgetType14 (OverlayPanel); IL00AE–00B0 calls SetFollowingSkinState(0,true).
- PUI Widget.SetFollowingSkinState 060027CC IL0009–000B proves argument0 selects background-follow flag and true enables it. Panel override 06003383 creates its rectangle when this is enabled.
- PUI Panel.ApplySkin 06003384 IL001F–0027 retrieves Skin.GetWidgetSkinColor(widgetType,background0); IL0052–0059 writes RectangleElement.FillColor. An optional SkinOpacity, if explicitly supplied, replaces alpha at IL003D–004D; MenuPanel ctor does not supply one.
- Theme SkinCreator.CreateSkinByComponentColorTable 06000009 IL00D0–00DB sets widget14 background to component array[4]. SkinCreator static ctor 06000003 IL0031–0039 maps component4 to palette color type3.
- ThemeConstantsWaveColor static ctor 06000013 bluePanelColorSet color3 IL042F–0449 = (3/255,29/255,97/255,1); bluePanelColorOpacityMapping component4 IL0DB7–0DBD =250/255. MakeComponentColorTable 0600000B combines these, using GetColorWithOpacity. Thus the constructor's .94 does not survive ordinary skin application.
- ThemeColorManager.SetThemeColor 06000030 updates skin0 and the PUI global skin. SetOverlaySceneThemeColor 06000031 independently updates skin1. CreateSkin 06000008 uses the requested theme's panel palette for skin0/1. Therefore actual user/scene theme determines color; the palette is not inferred from a screenshot.

Complete recovered OverlayPanel palette values are in overlay-palette.json, generated by palette_extract.py from the retained 06000013 receipt. Blue is (3,29,97); pink(160,54,67); red(66,5,0); navy(0,2,32); darkGray(40,39,54); gold(168,119,0); lightSteelBlue(32,104,127); purple(61,30,108); dualColor0(34,148,144); dualColor1(208,161,50); dualColor2(163,51,50); dualColor3(0,10,29); particle0(11,30,72); particle1(172,63,76); particle2(170,119,4); particle3(8,13,19). These named palettes use alpha250/255; default fallback is black alpha247/255.

The original right-edge child remains black alpha.30, width4, from MenuPanel ctor IL00CC–00FB. This child does not enable skin background following in the recovered ctor. White labels/focus are separate rendering inputs.

Uncertainty: the active theme/skin and accessibility state of an individual video/user are not established by static IL. High contrast may transform the palette. No claim of identical final screenshot pixels is made: skin alpha composites against the underlying scene, and ancestor opacity/transition can further change the visible result. The retained exact material is the correct starting point for the blue skin, replacing the unsupported constant constructor-only inference.
